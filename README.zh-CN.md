# Apple Music 桌面歌词

适用于 Windows 官方 Apple Music 应用的透明桌面歌词工具。使用 C#、.NET 8、WPF、Windows 媒体会话和 Win32 API；提供简体中文和英文界面。

**v0.2.5** 修复“原生歌词已缓存，但主地区目录返回空记录”的身份补全失败：现有 Apple 公开歌曲元数据查询可在严格限制内回退到其他地区，仍须通过原有身份、歧义及完整性检查。歌词原文、翻译和注音仍只读取 Apple 已有的本地文件；界面、独立翻译/注音开关和全局/单曲时间校正均未改变。v0.2.4 等旧版压缩包继续保留。

**尚未解决：全新歌曲在 Apple 歌词面板关闭时是否会产生原生缓存。** 此补丁只能识别已经落盘的歌词，不能获取未缓存的 Apple 歌词，也不能据此保证新歌曲无需打开面板就有原生翻译和注音。本工具不会打开或操作该面板。

## 启动中文版

1. 下载 `AppleMusicDesktopLyrics-0.2.5-win-x64-zh-CN.zip`，完整解压到可写目录，保留所有文件。
2. 双击 `Run-Portable.cmd`，设置窗口会打开。下载的是英文包时，也可以运行 `Run-Portable-zh-CN.cmd` 打开中文界面；若已有实例，请先从托盘退出再切换界面语言。
3. 在 Windows 官方 Apple Music 应用中播放歌曲。找到可靠匹配的同步歌词后，桌面歌词会自动显示。
4. 设置、显示/隐藏、锁定/解锁和退出均可从系统托盘菜单操作。关闭设置窗口后程序继续运行；再次启动会唤出已有实例的设置窗口。

中文版附带 `ui-language.txt`，首次直接运行 `AppleMusicLyrics.exe` 也默认使用中文。界面语言选择会保存。便携启动器把设置、日志及歌词缓存存放在程序旁的 `data` 目录；发布压缩包不包含个人数据。程序为 Windows x64 自包含版本，无需另装 .NET；要求 Windows 10 19041 或更高版本，或 Windows 11。请在与 Apple Music 相同的普通用户会话中运行。

## 歌词显示与同步

翻译和注音是本工具独立的两个开关，不会控制或跟随 Apple Music 内的开关。

| 显示翻译 | 显示注音 | 显示内容 |
| --- | --- | --- |
| 关闭 | 关闭 | 当前原文、下一句原文 |
| 开启 | 关闭 | 当前原文、当前句翻译 |
| 关闭 | 开启 | 当前原文、当前句注音 |
| 开启 | 开启 | 当前原文、当前句注音、当前句翻译 |

三行布局向上展开并保持底部位置。所需翻译或注音缺失时，回退到当前原文和下一句原文，并报告限制。原生数据保留语言标签和时间信息，按明确的行标识对齐。不会生成翻译、罗马音或虚构时间戳。

歌词慢约 1.75–2 秒时，在设置或托盘的全局时间校正中选择 **+1750 ms** 或 **+2000 ms**。正值让歌词提前，负值让歌词延后。全局校正对所有歌曲生效，立即保存并在重启后保留；单曲校正叠加在全局校正上。已有单曲校正时，可把当前歌曲的总校正应用到所有歌曲，程序会重算已保存的单曲差值，避免重复补偿。

锁定时，窗口背景透明、置顶、鼠标穿透且不抢焦点。可从托盘解锁后拖动位置；设置中可调整字体、颜色、宽度和透明度。显示器配置变化时程序会重新计算默认位置，或尽量保留自定义位置并限制在可见工作区。

## 原生歌词的限制

程序只读 Apple Music 已有的本地歌词缓存，优先使用本地公开歌曲目录信息严格匹配曲目。缺少身份信息时，仅把歌词缓存候选项中已有的数字目录 ID 发给 Apple 公开的 iTunes lookup 接口，读取歌名、歌手、专辑和时长。它不获取网络歌词、媒体地址、账号或令牌。请求限制为最多 128 个候选 ID、每批 20 个，跨地区请求也至少间隔三秒，八秒超时，并处理 429 等待要求及切歌取消。

v0.2.5 仅在查询成功、响应有效但待解析 ID 没有记录时尝试其他地区：主地区美国加最多三个备选地区。备选顺序在主地区查询后，只按仍未解析的 ID 确定，避免已解析候选项占用有限地区名额。原生歌词的语言/注音标签可优先安排相关地区，再参考 Windows 地区及 KR/JP/TW 默认顺序补足列表；这些线索只影响查询顺序，不能证明歌曲身份。HTTP 错误、超时、无效响应、冲突和限流不会触发切换地区。公开元数据在本工具自己的数据目录缓存 30 天，保存来源地区且各地区分开存储，原有美国目录缓存继续可用。独立的本地检查最多读取 32 个规范命名的地区元数据缓存文件，包括联网优先列表之外的地区；已知的跨地区身份冲突或超过本地检查上限时均拒绝原生匹配。

补充元数据后仍须严格匹配歌名、歌手、专辑、版本和时长，并确认目录 ID 与歌词资源一致。匹配不唯一、候选身份信息不完整、文件尚未写完或格式不受支持时，不会显示可能属于其他歌曲的内容。**此修复只帮助识别已经存在的歌词文件，不能取得尚未缓存的 Apple 歌词。** 没有原生缓存时，LRCLIB 可提供原文歌词；它不补充 Apple 的翻译或注音。无时间信息的歌词使用单独窗口查看，锁定的同步浮层不会为它虚构时间戳。

**本工具不会自动打开或操作 Apple Music 的歌词面板。** 尚未确认每首未缓存歌曲在面板关闭时都会产生原生歌词缓存，因此不能保证所有歌曲都有原生翻译和注音。缓存格式不是 Apple 公开支持的歌词接口，将来的 Apple Music 更新可能影响兼容性。程序不获取账号、密码、Cookie 或私人令牌，不读取受保护音频，不注入进程，也不修改 Apple Music 文件。

## 手动验证与故障排查

- 播放有歌词的歌曲，检查当前句和下一句；分别切换翻译、注音及同时开启。
- 暂停约三秒后继续播放，并在 Apple Music 内向前、向后拖动进度条，检查歌词是否重新对齐。远程控制跳转不是本工具的要求。
- 调整全局校正，切歌并重启，确认数值保留。
- 锁定后点击歌词所在区域，确认点击到达下方应用且焦点不变。
- 在实际显示器上更改分辨率和缩放比例，测试跨屏拖动及断开副显示器；混合 DPI 等硬件行为须在对应设备上验证。
- 启动后没有歌词时，先看托盘状态，确认 Apple Music 正在播放。若原生歌词缺少身份信息，等待公开目录查询完成，或通过托盘重试歌词查询；网络不可用、匹配不明确或只有无时间歌词时，透明同步浮层可能保持隐藏，可从托盘查看无时间歌词。重复启动应恢复设置窗口。完全退出请使用托盘的退出菜单。

详细自动化测试、实际 Windows 验证和未验证项目见 [v0.2.5 验证报告](docs/VALIDATION-0.2.5.md) 及 [发布说明](docs/RELEASE-0.2.5.md)；原生缓存说明见 [NATIVE-LYRICS.md](docs/NATIVE-LYRICS.md)。旧版验证报告继续保留。硬件相关行为和主观听感对齐不得仅依据单元测试认定已验证。工程日志和独立诊断工具仍使用英文。

## 从源码构建

```powershell
.\scripts\Build.ps1 -Publish
.\scripts\Package-Release.ps1
```

需要 .NET 8 SDK。依赖已经缓存时可添加 `-Offline`；该模式仅为本次还原跳过网络漏洞审计。构建脚本生成中英文两个独立目录，打包脚本生成两个便携 ZIP、源码 ZIP 和 SHA-256 清单，不覆盖已有发布压缩包。英文完整技术文档见 `README.md`。项目已公开：[LOVE4KIMCHAEWON/apple-music-desktop-lyrics](https://github.com/LOVE4KIMCHAEWON/apple-music-desktop-lyrics)。
