# Known limitations — 0.2.1

- **Native cache availability with the Apple lyrics panel closed is unverified for fresh tracks.** Existing cached payloads are readable without the overlay opening the panel. During one live check, HOT had matching catalog metadata (`1799278617`) but no native lyric payload. That observation does not establish why the payload was absent. The app never automatically opens or operates Apple Music's panel. LRCLIB can supply original lyrics when native data is absent; it cannot supply Apple's missing translation or pronunciation.
- **Translation and pronunciation are independent overlay preferences by design.** The app does not detect or synchronize Apple's visibility switches. This is the requested behavior, not a pending feature.
- Global offset is persistent within the selected data directory. Switching portable folders without retaining `data/settings.json` starts with default preferences. New installation defaults remain 0; choose +1750/+2000 ms when calibrating a late display. Global and per-song corrections add together; use the promotion command to avoid double-counting old song corrections. Listening-based confirmation remains necessary; queue-delay correction is not proof that every constant two-second discrepancy had that cause.
- The cache schema and filenames are Apple implementation details rather than a supported public lyrics API. The provider supports the observed `syllable-lyrics*.json` / `ttmlLocalizations` format. Older or changed formats, unsupported timing, unreadable files, incomplete writes, and bounded-scan failures withhold native output and allow original-lyrics fallback. One incomplete allowlisted payload can temporarily withhold native selection rather than risk incomplete identity discovery.
- Native matching requires complete title, artist, album, and duration, plus a unique cached catalog ID. Exact normalized text, compatible recording-version markers, and a three-second duration tolerance must agree. The lyric resource must have the same catalog identity. Missing fields, multiple matching IDs, contradictory metadata, or conflicting lyric payloads produce no native match. A newer file, plausible lyric duration, and similar title are not enough. This conservative policy can reject a correct recording; it cannot prove identity beyond the metadata Apple exposes.
- Translation/pronunciation coverage varies by song, language, and line. Supplemental text must reference an existing original key. Missing requested text or an unavailable language returns current/next originals with a tray limitation. Both-enabled output has three rows only when both requested supplemental lines exist. No replacement translation or romanization is generated. Some Apple-supplied metadata marks text `automaticallyCreated="true"`; native provenance does not imply human authorship.
- Raw TTML, language tags, timing, spans, and metadata are retained. Unknown Apple offset attributes are preserved without applying undocumented semantics. Sequential TTML timing and malformed or ambiguous references are rejected. The app uses line-level highlighting; preserving syllable timing does not implement word-by-word karaoke.
- The real playback exercise recorded pause/resume, backward paused repositioning and a forward playing discontinuity. Audible accuracy and repeated forward/backward scrubbing reliability remain **unverified**; intermediate/provider-correction positions can briefly appear while dragging. Simulated seeks and recalibration are also tested. Remote seek support is unnecessary; the app sends no playback commands.
- Native integration testing used Windows 10 build 19045, x64, a 1920×1080 primary display at 125% scaling, and Apple Music 1.1792.39681.0. Windows 11, 1440p/4K hardware, other scaling values, multiple monitors, monitor removal, mixed DPI, and taskbar/work-area changes await manual acceptance testing. Geometry simulations do not verify Windows display-event delivery or physical rendering.
- Default placement follows the selected monitor's bottom center; custom placement is preserved where visible and clamped after display changes. Confirm these behaviors on the intended hardware, including three-row expansion and monitor disconnection. Tray Reset position remains the recovery path.
- Locked/edit styles, passive hit testing, transparency, and placement have been audited. Physical click-through, dragging, tray use, and keyboard focus preservation still need end-user checks. An equal zero `GetForegroundWindow` handle before and after a diagnostic is not evidence of preserved focus.
- Apple metadata and timeline updates are not atomic. A new title can briefly coexist with the previous duration or an invalid timeline. Debouncing, strict matching, cancellation, and late-cache handling reduce stale output; rapid navigation and long-running use require more live validation. Interpolation depends on the player's rate and timeline; missing or stale playing timelines hide synchronized output.
- GSMTC exposes no direct PID for executable-named sessions. Package-family validation corroborates Apple Music source identity; it is not an OS-provided direct session/PID association. Apple Music sometimes places album text inside the artist field; the conservative em-dash normalization may not cover every metadata variant.
- LRCLIB coverage and timestamp quality vary. Missing/ambiguous versions are rejected. Network failures and rate limits can leave no lyrics; use Retry after the reported cooldown. This run's real request was blocked by the validation environment's refused proxy connection, so no v0.2.0 live-network success is claimed. Automated HTTP/cache/error tests passed. Plain lyrics remain untimed. Imported LRC is a current-track override until track change or retry; it does not add native supplemental data.
- Long lyrics use a single-line ellipsis. Unicode rendering depends on installed fonts. Local LRC supports UTF-8 and Unicode BOM encodings; legacy code-page files may require conversion to UTF-8.
- Startup is opt-in through HKCU Run and points to the current executable/data directory. Moving a portable folder may require toggling startup off/on. No startup registry change was exercised during automated validation.
- The portable self-contained build is unsigned. There is no installer, updater, fullscreen karaoke interface or album-art display. Existing v0.1.0/v0.2.0 releases are preserved; v0.2.1 uses a separate versioned publish directory.
